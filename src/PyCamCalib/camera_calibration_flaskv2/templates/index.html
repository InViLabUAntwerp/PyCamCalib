Why are there two runtime options?

  • Browser Runtime (Preferred): This option runs entirely inside your browser memory using Pyodide. We strongly encourage using this if possible because it uses your own device's compute and memory rather than costing us money to run on our servers. However, because it is more difficult to maintain, it may occasionally lack newer features.
  • Flask Backend Server: This option utilizes the compute and memory of our server, which incurs financial costs for us. To manage these server expenses and prevent system overload, this path has strict limitations on uploads and concurrent users.

Browser Runtime (WASM)

Runs locally inside your browser memory using Pyodide. Keeps data private and saves server resources.

  • Uses your device's compute & memory
  • No file size or upload limits

Flask Backend Server

Hosted processing

Processes images on our server. Consumes our server resources which costs money, so capacity limits apply.

  • Max upload size: 50MB
  • Capped at 8 concurrent users
  • Instant startup time
